🔄 Functions, Lists, and Dictionaries

From Script-Kiddie Code to Software Architecture

💡 Critical Insight: This is where you go from writing script-kiddie code to actual software architecture. In FinTech, you deal with massive amounts of customer data. Lists store that data, dictionaries organize it, and functions process it.

1. Functions (Week 6)

Functions are reusable blocks of code. You write the logic once and use it everywhere. The key to scaling code from 100 lines to 100,000 lines without losing your mind.

The Three Core Concepts

📝 Definition

Start with def, give it a name, pass parameters in (), and end with :

def greet(name):
    print(f"Hello, {name}!")

greet("Ali")  # Output: Hello, Ali!

🎯 CRITICAL: Return vs. Print

Print: Just displays text to the console. The data is lost.

Return: Gives data back to the program so you can use it in calculations.

# WRONG - Just prints, doesn't return
def calculate_tax_wrong(salary):
    tax = salary * 0.10
    print(tax)  # Data is gone after this line!

# CORRECT - Returns the value
def calculate_tax(salary):
    tax = salary * 0.10
    return tax  # Now we can use it!

final_salary = calculate_tax(100000)  # Use the returned value
print(final_salary)  # Output: 10000.0

🔍 Variable Scope: Local vs. Global

Local Variables: Created inside a function. They die when the function ends.

Global Variables: Created outside a function. Can be read anywhere.

# Global variable - accessible everywhere
bank_name = "Habib Bank Limited"

def open_account(customer_name):
    account_id = "ACC001"  # Local - only exists here
    print(bank_name)  # Can use global variable
    return account_id

open_account("Muid")
print(account_id)  # ERROR! account_id doesn't exist outside the function

Default Parameters

⚙️ Make Functions Flexible

You can set default values for parameters. When the function is called without providing that parameter, it uses the default.

def calculate_tax(salary, tax_rate=0.10):  # 0.10 is the default
    return salary * tax_rate

print(calculate_tax(100000))  # Uses default: 10% tax
print(calculate_tax(100000, 0.20))  # Override: 20% tax

2. Lists & Tuples (Week 7)

You need to store 10,000 transactions. You don't make 10,000 variables. You make a list.

Lists (Mutable) vs Tuples (Immutable)

Feature Lists [] Tuples ()
Changeable? ✅ Yes (Mutable) ❌ No (Immutable)
Speed Slower Faster
Use Case Dynamic data (transactions) Fixed data (coordinates)
Safety Can be modified accidentally Protected from changes

Lists: The Workhorses

📋 Common List Operations

# Create a list of transactions
transactions = [100, 250, 300, 400, 500]

# Add an item to the end
transactions.append(600)

# Remove a specific item
transactions.remove(300)

# Get the length
print(len(transactions))  # Output: 5

# Access by index (starts at 0)
print(transactions[0])  # First item: 100
print(transactions[-1])  # Last item: 600

Slicing: The Secret Weapon

🎯 Extract Portions of Lists

list[start:end] gets items from index start up to (but not including) end

# Slicing examples
daily_sales = [100, 250, 300, 400, 500]

# Get items from index 1 to 3
print(daily_sales[1:4])  # [250, 300, 400]

# Get the last item
print(daily_sales[-1])  # 500

# Get the last 3 items
print(daily_sales[-3:])  # [300, 400, 500]

# EXAM TRICK: Reverse the whole list
print(daily_sales[::-1])  # [500, 400, 300, 250, 100]

Tuples: Fast & Immutable

🔒 When to Use Tuples

Perfect for fixed data like an employee's ID or fixed GPS coordinates. Once created, they cannot be changed.

# Employee's fixed information
employee = ("EMP001", "Muid Ahmed", 45000)

# Access values
print(employee[0])  # EMP001
print(employee[1])  # Muid Ahmed

# This will cause an ERROR - tuples are immutable
# employee[2] = 50000  # TypeError!

3. Dictionaries (Week 8)

This is the most critical data structure for business systems. It uses Key-Value pairs for lightning-fast, O(1) lookups.

The Dictionary Structure

🗝️ Key-Value Pairs

Format: {"key": "value"}. Keys must be unique and are usually strings or numbers.

# Simple dictionary
customer = {
    "name": "Muid Ahmed",
    "account_id": "ACC001",
    "balance": 45000,
    "is_verified": True
}

# Access values by key
print(customer["name"])  # Muid Ahmed
print(customer["balance"])  # 45000

Safe Access with .get()

⚠️ CRITICAL: Never Crash Your Program

Never use dict["key"] if you aren't sure the key exists. It will crash the program with a KeyError.

# WRONG - Will crash if key doesn't exist
if customer["age"] > 18:  # KeyError!
    print("Adult")

# CORRECT - Safe access with default value
age = customer.get("age", 0)  # Returns 0 if "age" doesn't exist
if age > 18:
    print("Adult")
else:
    print("Age not provided, defaulting to 0")

Updating & Adding to Dictionaries

📝 Modify Dictionary Data

# Update existing value
customer["balance"] = 50000

# Add new key-value pair
customer["phone"] = "+92-300-1234567"

# Remove a key
del customer["is_verified"]

# Check if key exists
if "phone" in customer:
    print("Phone exists")

Master-Level: Nested Dictionaries

💎 Real-World Example: Bank Ledger

# Dictionary of dictionaries
bank_ledger = {
    "ACC001": {"name": "Muid", "balance": 45000},
    "ACC002": {"name": "Avisha", "balance": 120000},
    "ACC003": {"name": "Ali", "balance": 85000}
}

# Access nested values
print(bank_ledger["ACC001"]["name"])  # Muid

# Iterate through and display all accounts
for acc_id, details in bank_ledger.items():
    print(f"Account: {acc_id} | Owner: {details['name']} | Balance: {details['balance']}")

Dictionary Iteration Methods

🔑 .keys()

for key in customer.keys():
    print(key)

Iterate through all keys only

💰 .values()

for value in customer.values():
    print(value)

Iterate through all values only

⚙️ .items()

for k, v in customer.items():
    print(k, v)

Iterate through both key AND value

🔄 .get()

value = customer.get(
    "age", "N/A")

Safe access with default value
